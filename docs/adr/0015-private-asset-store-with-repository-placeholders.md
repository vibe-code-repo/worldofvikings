# ADR-0015: A private asset store outside the repository, with placeholders inside it

- **Status:** accepted
- **Date:** 2026-09-06
- **Deciders:** project maintainers

## Context

The project is taking over the world-building assets of an earlier, private
the source engine project (_the source project_): environment meshes, vegetation, rocks,
terrains and their textures, recovered from an the export tool export. There are
roughly 470 candidate files and about 200 MB of them.

Three facts collide.

**The licences are not settled.** The export carries no `LICENSE`, no `README`
and no credits file. Shader names (`Vendor_VegitationShader`,
`Vendor_WaterShader`, `Shader Graphs_POLYGON_CustomCharacters_URP`) place
the low-poly `SM_*` family in a third-party vendor' POLYGON range, but the high-poly
photo-textured trees (14k–28k triangles, 1024 px photographic leaves) do not
match third-party's flat-shaded look at all and come from a second, unidentified pack.
Per-file redistribution rights therefore cannot be asserted today for any of it.
Spec §46 and AGENTS.md §7 are unambiguous: nothing without redistribution rights
goes into this repository.

**The repository must stay a repository.** It is public and MIT-licensed, and
agent rule 20 says a clean clone must remain easy to start. Two hundred
megabytes of binaries whose licence is `NOASSERTION` fails both halves.

**The game still has to run.** Development cannot wait for a licence review, and
a clone that fails to load half its world with a stack trace is not "easy to
start".

The existing machinery had no answer for any of this: `assets/manifest.json`
version 1 recorded only `path`, `bytes` and `hash`, provenance lived as free
text in `docs/asset-licenses.md` joined to it by nothing but a path string, and
`AssetManager` built one URL and loaded it.

## Decision

**Assets whose redistribution rights are unsettled live in a private store
outside the repository.** Physically `wov-dev:/srv/assets-export/store/`, served by
the same asset server under `/store/…` when `WOV_ASSET_STORE` points at it.
Nothing about it is a secret — it is a holding area for files this project may
not yet hand to third parties.

**The manifest describes both halves and carries provenance per file.**
`assets/manifest.json` moves to version 2. Every entry gains `id`, `kind`,
`bounds`, `origin`, `source`, `author`, `license`, `redistributable`,
`visibility` and — for private assets — `placeholder`. Provenance stops being a
Markdown table nothing verifies and becomes a schema-checked field: `license` is
validated as non-blank text, so an asset without a licence statement cannot be
listed at all. Version 1 manifests are migrated on read (everything unknown
becomes `NOASSERTION` / `unknown`, nothing is invented).

**Every private asset has a placeholder committed in the repository.** A box
with the same hull box and the same root node name, generated by the import
pipeline, under 20 kB. That is what a clone without store access loads.

**The client falls back and says so.** `AssetManager` takes an optional asset
catalog. A `private` asset is requested from the store; on a 404 the manager
loads the placeholder instead and counts it. `summarizeAssetSources()` renders
`assets: N private, M placeholder`, which the game shows and the smoke test
asserts — so "the store is not reachable" is visible instead of silent.

**Releasing an asset is a two-line change.** Copy the file into `assets/`, flip
`visibility` to `public`, drop the `placeholder`, fill in the real licence.

## Alternatives considered

| Alternative                                           | Why not                                                                                                                                                                                                             |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Commit the assets and sort the licences out later     | Directly forbidden (spec §46, AGENTS.md §7), and git history makes "later" irreversible.                                                                                                                            |
| Git LFS                                               | Still distribution, just with a different transport, and it adds a required tool for a normal clone (agent rule 18).                                                                                                |
| A private git submodule                               | Turns "clone and run" into "clone, get access, clone again". A clone without access fails instead of degrading.                                                                                                     |
| Keep provenance only in `docs/asset-licenses.md`      | It is joined to the manifest by a path string and checked by nobody. With 470 files, a table that drifts silently is worse than no table.                                                                           |
| Let the client read `assets/manifest.json` at runtime | The manifest is Zod-validated and 470 entries long; `game-must-not-pull-in-the-manifest-schema` exists precisely to keep it out of the bundle (ADR-0012). The catalog the client takes is a plain, Zod-free lookup. |
| No placeholders — just let private assets 404         | The scene would be missing objects with no visible reason. A grey box that is the right size is a statement; a hole is a bug report.                                                                                |
| Placeholders as one shared cube, scaled at placement  | Scale would then live in world data, so the day an asset is released the world file has to change too. A per-asset box with the real hull keeps the swap to one manifest field.                                     |
| Serve the store from a second port                    | Two hosts to configure, two CORS surfaces, and `VITE_ASSET_URL` stops being the one answer to "where do assets come from".                                                                                          |

## Consequences

**Positive** — the repository stays clean, MIT and small; a clean clone runs
with no store, no `.env` and no credentials, and says out loud which assets it
is standing in for. Provenance is machine-checked per file. Releasing an asset
is a manifest edit, not a migration. `pnpm validate:assets` verifies the store
when it can reach it and skips with a message when it cannot, so contributors
without the store are not blocked by a check they cannot satisfy.

**Negative** — there are now two places an asset can live and a fallback path
that only fires when something is missing, which is exactly the kind of code
that rots untested; it is covered by unit tests and by a smoke assertion.
Placeholder GLBs are generated files that are nevertheless committed — the one
deliberate exception to "nothing generated is committed" (AGENTS.md §5.7),
because their whole purpose is to exist in a clone that cannot run the
generator. The private store is not backed up by this repository: `store/` is
Mike's to keep.

**Follow-ups** — the licence review per pack is open (see
`docs/asset-licenses.md`); until it lands, everything imported is
`license: NOASSERTION`, `redistributable: false`. Serving the store to anyone
but the developer needs access control the asset server does not have — today
it is bound to localhost and rsynced to a host behind SSH.
