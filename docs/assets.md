# Assets

> Status: **Phase 1, plus the world-asset import.** Folders, the local asset
> server, the loading/caching asset manager, scene placement and the manifest
> check exist. A CC0 barrel from Kenney's Retro Fantasy Kit, an imported building
> and an imported terrain patch are loaded by the game and asserted by
> `pnpm smoke`.

## Where assets live

Assets live in **two** places (ADR-0015).

| Visibility | Bytes live in                           | Served at  | In a clean clone     |
| ---------- | --------------------------------------- | ---------- | -------------------- |
| `public`   | `assets/` in this repository            | `/…`       | present              |
| `private`  | the asset store, outside the repository | `/store/…` | absent → placeholder |

Both are served locally by the asset server on http://localhost:9000
(`pnpm dev:assets`); the store only when `WOV_ASSET_STORE` points at it. In
production the same paths come from `assets.world-of-vikings.com` (spec §37).

The store exists because the redistribution rights of the 454-file private asset
collection are not settled, and this repository is public and MIT (spec §46). It is a holding area, not a secret: clearing an asset for release
means copying it into `assets/` and flipping one manifest field.

Code never hardcodes a host: it resolves references through `@wov/asset-system`
with `VITE_ASSET_URL`, and the store through `VITE_ASSET_STORE_URL` or the
default `/store` prefix on the same host.

## Placeholders, and why a clean clone still runs

Every private asset has a **placeholder** committed under
`assets/placeholders/`: a grey box with the same hull box and the same root node
name, under 20 kB, generated by the import pipeline. When the store answers 404 —
which is the normal state of a clone that has no store — `AssetManager` loads
that instead of losing the object, and the game says so on screen:

```text
assets: 2 private, 0 placeholder     # the store answered
assets: 2 private, 2 placeholder     # no store: boxes, and it says so
```

That line comes from `summarizeAssetSources`, and `pnpm smoke` asserts it. A
missing store is meant to be visible, not silent.

## Loading them

`@wov/asset-system` owns loading too. `AssetManager.loadGlb(path)` loads a GLB
into a Babylon `AssetContainer` and caches it per resolved URL, so placing the
same model a hundred times costs one request; `instantiate(path)` makes the
copies and `placeAssets(manager, placements)` moves them where they belong.
Babylon.js registers no file loader by itself, so the glTF plugin is registered
explicitly and the registration is covered by a test. See ADR-0011, ADR-0012 and
the package README.

The manifest schema sits behind its own entry point, `@wov/asset-system/manifest`
— it is the only part that needs Zod, and the game does not read the manifest.
What the game _does_ read is an **asset catalog**: the two fields loading
actually needs (`visibility`, `placeholder`) as plain data, built by the caller
from world data or a fixture. That is what keeps 900 Zod-validated manifest rows
out of the browser bundle (ADR-0012, ADR-0015).

## The manifest

`assets/manifest.json` (version 2) records every file the game can download — in
`assets/` **and** in the store — with its size, a SHA-256 hash, its hull in
metres, and where it came from: `origin`, `source`, `author`, `license`,
`redistributable`, `visibility` and, for a private asset, its `placeholder`.

`license` is validated as non-blank text, so an asset without a licence
statement cannot be listed at all (spec §46). Provenance is therefore checked
rather than merely written down; `docs/asset-licenses.md` is the summary a
person reads, grouped by set.

`pnpm validate:assets` (part of `pnpm validate` and `pnpm check`) checks four
things:

1. the manifest is a valid manifest;
2. the public entries match the files in `assets/`;
3. every private entry has its placeholder committed;
4. the private entries still match the store — **only when `WOV_ASSET_STORE` is
   readable**, and skipped with a message when it is not, so a contributor
   without the store is not blocked by a check they cannot satisfy.

`pnpm validate:assets --write` re-measures sizes and hashes. It never invents
provenance: an undeclared file fails with a message instead.

Version 1 manifests still read — they are migrated, with everything version 1
could not say spelled out as `NOASSERTION` / `unknown` rather than guessed.

The hash is also what immutable, cache-forever production file names will be
built from (`immutableAssetPath`, §37). Nothing serves those names yet.

## Importing assets from a modelling export

`tooling/asset-pipeline/` turns a modelling export — one GLB per model, PNG
textures — into store files, placeholders and manifest entries:

```bash
pnpm import:world-assets --source ~/assets/export --store ~/assets/store
pnpm import:world-assets --source … --store … --dry-run
rsync -a --delete ~/assets/store/ wov-bau:/srv/assets/store/
```

It is deterministic and idempotent: the same input produces byte-identical files
and a byte-identical manifest. What it selects, how it treats an origin and what
provenance it asserts are documented — with the measurements behind each — in
`tooling/asset-pipeline/README.md`.

## Art direction (spec §23)

Modern stylized low-poly fantasy: chunky simplified geometry, large polygonal
surfaces, readable silhouettes, subtle hand-painted look. No photorealism, no
scanned materials, no micro detail.

## Performance rules (spec §38)

Instancing and thin instances, LOD, frustum culling, object pooling, async
loading, zone streaming, limited dynamic lights, selective shadows. Target:
60 FPS on a typical modern desktop.

## Contribution rules (spec §46)

Every asset must document **source, author, license, usage rights and
modification status** in `docs/asset-licenses.md`. Never commit unknown-license
files or anything without redistribution rights.
AI-generated assets need their provenance documented too.

Third-party files are vendored byte-identically, keeping the source layout, in a
folder named after the kit; a `README.md` next to them holds the full provenance
record and `THIRD_PARTY_NOTICES.md` the per-kit credit (ADR-0012). "Modified: no"
should stay a claim that `sha256sum` can settle.

An asset whose rights are not settled does not go into `assets/` at all — it goes
into the store as `visibility: private`, `license: NOASSERTION`,
`redistributable: false`, and is listed in `docs/asset-licenses.md` under an open
review (ADR-0015).
